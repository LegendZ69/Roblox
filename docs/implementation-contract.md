# Implementation contract

Internal integration contract for the initial implementation. See the game plan for intended behavior.

## Config (root owns)

`src/shared/Config.luau` is a pure module. `Config.Projects` is a dictionary keyed campfire/bridge/beacon, each with label, cost (wood/stone), prerequisite (nil or project ID), position {x,y,z}. `ProjectOrder` is ordered IDs. `Nodes` maps IDs wood1..wood6, stone1..stone4 to {kind, position, prerequisite}; `Resources[kind]` has label, yield, cooldown. `RepairStations` maps repair1..repair3 to positions. Positions are local offsets from a plot origin, with interaction height near y=5. Plot origin Y=0, top of ground Y=0. World uses geometry top surfaces at Y=0 and characters spawn at Y=5.

Constants: MaxPlayers=4, InteractionDistance=18, EventDuration=90, EventCooldown=180, RepairCooldown=5, LeaseSeconds=120, AutosaveSeconds=30. Event reward wood=24/stone=12. Event required work = 8 + 4 * participants. Project costs campfire=12 wood; bridge=30 wood; beacon=40 wood+20 stone. Save record schema: schemaVersion=1, ownerId, stockpile={wood,stone}, projects={campfire,bridge,beacon boolean}, tutorialStage=number, nextEventAt=unix, eventSerial=integer, lastRewardEvent=integer.

## Domain (island_rules agent owns Island.luau and tests/Island.spec.luau)

`Island.new(ownerId, record?)` creates state; `Island.defaultRecord(ownerId)` returns a fresh profile; `Island.validateRecord(record, ownerId)` returns validRecord or nil, reason. Do not silently replace invalid profiles. `island.record` is current persistent record. `island.ownerId`; `island.helpers` map numeric user IDs to true; `island.accepting` boolean; `island.event` transient event data. `island:setHelper(userId, allowed)`; `island:close()` closes mutation/cancels unfinished event. `island:canEdit(userId)`; `island:snapshot(now)` returns detached view of all persistent game data plus event, accepting, and harvest availability. `island:act(actorId, action, now, context)` returns `{ok:boolean, message:string, changed:boolean?}`. action = {kind='harvest'|'build'|'startEvent'|'repair', target=string?}; context={distance:number, alive:boolean, participants:number?}, all context server computed. Non-owner cannot start event. startEvent requires beacon + cooldown and uses participants (clamped 1..4). `island:tick(now)` resolves timeout/cooldowns; returns true if view changed. All mutation routines MUST NOT yield. Repair target IDs come from Config. Event shape for client: {phase='active'|'success'|'failed', endsAt=number, progress=number, required=number, serial=number}; or nil. Snapshot includes `ownerId, stockpile, projects, tutorialStage, nextEventAt, event, helpers` plus `nodes` mapping ID to next available UNIX time. Helpers must be an array of userIds in snapshot, not numeric dictionary (Roblox serialization).

Config loading in pure domain: `local Config = if script then require(script.Parent.Parent.Shared.Config) else require('../shared/Config')` OR equivalent Roblox hierarchy: domain resides ServerScriptService.Server.Island; Shared is ReplicatedStorage.Shared, so use game:GetService('ReplicatedStorage').Shared.Config for runtime. Prefer if game ~= nil then ... else relative require. Tests run under official standalone Luau CLI.

## Persistence (persistence agent owns Persistence.luau and tests/Persistence.spec.luau)

Pure dependency-injected manager: `Persistence.new(adapter, options)` where adapter:update(key, transform) returns `ok, valueOrError`; transform(current) returns next envelope or nil to cancel. options={sessionId:string, now:()=>number, leaseSeconds:number}. `manager:load(ownerId, defaultRecord)` returns record or nil, reason. defaultRecord is a table supplied by root; manager must NOT modify it. `manager:save(ownerId, record)` returns boolean, reason?; `manager:release(ownerId, record)` returns boolean, reason? (flush + unlock); `manager:abandon(ownerId)` drops local ownership without storage write; `manager:isOwned(ownerId)` returns bool and local known lease expiry? Root will renew by save every30s; record schema validation done by Island before load result is made playable, but persistence envelope malformed data must not be treated as new. Envelope uses data + sessionId + leaseUntil + revision; default only when current key is truly nil. Recheck token/lease on every transform including retries. Copy snapshots before yielding. No task/game references in pure module. Production root adapter wraps DataStore UpdateAsync in pcall with bounded retries; Studio default is deliberate shared in-memory adapter, visibly labeled in UI.

## Multiplayer session

`Session.new(ports)` creates a pure server coordinator. It owns registered player identities, each player's current island, temporary invitations, and a shared prompt/remote request budget (12-request burst, 5 requests per second per player). `add(userId, displayName)` registers once; `current(userId)` returns the active island ID; `travel(userId, ownerId?)` selects an available island or the hub; `view(userId)` returns detached sorted player/invitation arrays. Negative Studio IDs are valid.

`request(userId, payload, promptOwnerId?)` is the production entry point for both remote and prompt actions. It accepts only the documented client action kinds, strips untrusted extra fields, and invokes the real island model. The optional owner ID comes only from server-created world prompts; remote clients cannot select it. Storm participation counts registered, living, authorized players currently on the host island. Unknown and malformed requests produce no broadcasts, notices, travel, or economic mutation, but consume a registered player's rate budget.

All ports are synchronous and must not yield: `now`, `clock`, `maxPlayers`, `island(ownerId)` (active model or nil), `isOwned(ownerId)`, `alive(userId)`, `facts(userId, ownerId, action)` (server distance/alive), `move`, `notice`, `changed`, `freeze`, `sync`, and `broadcast`. Main supplies Roblox character/transport effects and persistence ownership. The coordinator does not load, save, render, or own Player instances.

`closeIsland(ownerId, message)` clears that host's outgoing invitations and returns visitors home. Main closes the model before calling it on pause/shutdown. `remove(userId)` also removes the player from the roster, clears their request budget and incoming invitations, and revokes their helper access on all other active islands. Main then closes/releases their runtime. `tick()` expires invitations; acceptance also checks the deadline directly. Engine join/leave handlers reject stale Player instances before entering the coordinator. Lifecycle callers broadcast after completing their updates.

Cloud tests call this public interface with real Island/Persistence modules and controlled ports. Engine scheduling, Player events, movement physics, and actual networking still require Studio.

## World (world_builder agent owns World.luau only)

Server module `World.create(config)` returns world. Generate attractive stylized island world, hub, water, lighting and named empty plot pads. Methods: `world:addIsland(ownerId, slotIndex, displayName, snapshot)` returns plot; `world:removeIsland(ownerId)`; `world:updateIsland(ownerId,snapshot)` constructs projects, bridge/outcrop visibility, node state, event repair prompts; `world:getSpawn(ownerId)` returns CFrame, nil means hub; `world:getTargetPosition(ownerId,kind,target)` returns Vector3 or nil. Prompt callback: world.onAction = function(player, ownerId, action) root-supplied; set for harvesting/building/repair/startEvent. Prompt triggers MUST NOT directly mutate economic state. Each world-generated prompt holds ownerId/action info; runtime callback goes through authoritative root dispatch. getTargetPosition uses exact same positions as prompts; kind startEvent points at beacon. World instances parent Workspace.DriftwoodIsles; no model assets or remote dependencies. `world:updateIsland` called after state changes and once/second, so avoid rebuilding unchanged geometry. Prefer stage caches and update only visibility/prompt enabled state. Bridge should connect mainland eastern shore x=38 to stone outcrop centered x=66 with stable collision. Root manages teleportation.

## Client action policy

`ReplicatedStorage.Shared.ClientPolicy` is a pure module used by both HUD button eligibility and outbound requests. `canEdit(snapshot)` follows active server-granted editing permission. `canRequest(snapshot, localUserId, action)` allows initial synchronization before a snapshot, then safe Home/Visit/invitation responses even when the personal profile is loading or unavailable. Host selection and invitation controls use the latest roster and invitation list. Economic actions still require an active editable island; storm start and crew management remain owner-only. This policy improves controls, not server security: Session and Island validate every request independently.

Home can return to the hub if the personal island is unavailable. When a profile finishes loading, Main preserves `Session.current` instead of interrupting a chosen visit. Post-yield admission/load checks revalidate shutdown, player presence, and runtime closure before proceeding. Cloud tests cover policy and session behavior; engine scheduling and GUI input remain part of Studio validation.

## Client (island_ui agent owns Main.client.luau only)

`ReplicatedStorage.Shared.Guidance.present(snapshot, now, localUserId)` is the pure snapshot-to-view boundary used by the actual HUD for objective text, project card costs/eligibility, role, save labels, and storm status/progress. It uses ClientPolicy for action eligibility and never mutates saved progress or predicts rewards. Paused-state and visitor guidance take precedence over storm instructions. Clock input comes from the server snapshot plus elapsed local time. Returned view data is detached. Tests exercise this public presentation boundary; no GUI rendering is simulated.

Runtime ReplicatedStorage.Shared.Config, ReplicatedStorage.Remotes.Action (RemoteEvent client→server), State (RemoteEvent server→client). Client sends `{kind='sync'|'invite'|'acceptInvite'|'declineInvite'|'revoke'|'visit'|'home'|'harvest'|'build'|'startEvent'|'repair', target=string? , userId=number?}`. Gameplay normally via world prompts; HUD may send build/startEvent against current island, subject to distance checks. Server sends envelope `{kind='snapshot', island=snapshotOrNil, ownerName=string, isOwner=bool, canEdit=bool, saveStatus='loading'|'session'|'pending'|'saved'|'saving'|'recovery', studioMode=bool, players={{userId,displayName,hasIsland}}, invites={{ownerId,ownerName}}, now=unix}`; notice `{kind='notice',message=string,ok=bool}`. State current island only. Client retains UI while nil/loading, requests sync on ready, and interpolates timers using envelope.now + elapsed local time. Owner invitations selected from players list; user must explicitly accept using invites list. visit={userId=target owner}: only accepted helper allowed by root (uninvited visual visits can later be viewing via visit same command; implemented as read-only visitors, no edits). All player list IDs are numbers. ownerName not identity authority. UI shows island owner, wood/stone, three projects, next objective, event progress/cooldown, save status and helper/invite management. Responsive desktop + phone, no plugins/assets. Island snapshot event/helper schema above. Invite accepts auto-visit, revocation returns helper home. No client currency mutations.

## Ownership

Root owns bootstrap integration, Config, default.project.json, docs, and README. Other agents must not edit outside assigned files without messaging root. Never commit or push; root integrates then publishes feature branch and PR. Syntax is Luau with strict checking where feasible; no unverified external libraries.
