# Driftwood Isles 0.1.0-alpha.2

This alpha improves recovery controls, server shutdown handling, and release integrity without changing the island economy or save schema.

If your personal island is loading or unavailable, Crew still lets you visit friends or accept/decline an invitation after receiving server state. Accepted helpers contribute only to their host's saved island; no replacement personal profile is created. Home returns to the hub when necessary. Finishing your personal profile load no longer interrupts a chosen visit.

The server rechecks shutdown and player/runtime closure after waits before admitting or retrying a profile load. The place verifier now rejects unsupported root directives and mismatched property types and preserves exact integer values. Release retries can select the original reviewed main-history commit, and the setup ZIP includes all linked guides.

Cloud verification: **50 Luau behavior groups**, **45 Python tooling tests**, strict core analysis, formatting, place compilation/build verification, and deterministic package/source checks. These tests cover the production client eligibility policy, session/domain behavior, and release tooling; the small engine lifecycle guard changes are source-reviewed and compiled, not exercised under Roblox scheduling.

Download `DriftwoodIsles-0.1.0-alpha.2.rbxlx` or the matching setup ZIP. Open the place in Roblox Studio on Windows or macOS and press **Play**. Studio defaults to session-only saving. The manifest records the exact source commit, and `SHA256SUMS` verifies the files.

**Still pending:** Roblox Studio rendering, physics, actual two/four-client transport, engine scheduling, real DataStore networking, device controls/performance, and measured pacing. This GitHub prerelease does not publish a live Roblox experience.
